Setup & deploy

Two minutes on your machine. Hosting is only needed if you publish Mapwright for others, and it fits in free tiers.

This guide covers four things, in the order you will need them:

  1. Install Mapwright on your machine (the tool itself, 2 minutes)
  2. Connect your coding agent (Claude Code, Cursor, VS Code, Windsurf, Gemini, Codex, opencode, others)
  3. Add the editor extension (optional)
  4. Publish the website and the packages for free (only if you want to share Mapwright with others)

The short version of the deploy plan: the MCP server and the map run on each developer's own machine; only the website (and, optionally, the packages) need hosting, and all of it fits in free tiers.

1. Install

Requirements: Python 3.10 or newer. Nothing else: Mapwright has no runtime dependencies.

pipx install mapwright-agent            # from PyPI (the command is `mapwright`)
pipx install ./mapwright-0.1.0          # or from the unzipped folder

or, without pipx:

pip install ./mapwright-0.1.0

See RELEASING.md for publishing. The PyPI name mapwright is taken by another project, hence mapwright-agent.

Check it works:

mapwright --version
mapwright guide

Optional: pip install pyyaml makes Docker Compose and Kubernetes parsing more complete. Without it a small built-in parser handles common files.

Track a project

cd your-project
mapwright init

This records the current state as step 0 (baseline). History is stored outside the project, in ~/.mapwright/projects/<project>/. Nothing is written into your repository unless you connect an agent or ask for notes in AGENTS.md.

Open the map

mapwright open

This starts the local daemon (http://127.0.0.1:7979) if it is not running and opens the browser. The link carries a local token; don't share it. Stop the daemon with mapwright down (full list in COMMANDS.md).

2. Connect your agent

See what is installed and what is connected:

mapwright connect --list

Connect one (project scope writes into the project; --scope user connects it for every project):

mapwright connect claude-code

Restart the agent, or start a new session, so it loads the MCP server.

Existing config files are merged, never replaced. A copy of each file is saved in ~/.mapwright/backups/ before it is changed. A file that is not plain JSON (for example with comments) is left alone, and you are told to paste the snippet yourself.

Claude Code plugin (alternative to connect)

The repository root contains a plugin marketplace. In Claude Code:

/plugin marketplace add <path-or-github-repo-of-mapwright>
/plugin install mapwright

The plugin brings the MCP server, the hooks and the skill. It needs mapwright on your PATH.

Tell the agent (optional)

The MCP server already sends short instructions. If you want them in your instructions file too:

mapwright agents-md --file CLAUDE.md

(AGENTS.md, GEMINI.md and .cursorrules work the same way.) For agents that read Agent Skills, copy integrations/skills/mapwright/ into the agent's skills folder (for Claude Code: .claude/skills/). The skill also explains the shell fallback (mapwright brief, mapwright step …) for agents without MCP.

Check

mapwright doctor

The Connect panel in the UI shows the same, with buttons to connect and disconnect.

3. Editor extension (optional)

For VS Code, Cursor, Windsurf and VSCodium:

code --install-extension integrations/vscode/mapwright-vscode-0.1.0.vsix

(Cursor: cursor --install-extension …; or drag the .vsix onto the Extensions view.)

It adds Mapwright: Open Map (beside your code), Record Step, Copy Agent Brief, Connect an Agent, and a status bar item with the current step, pending changes, open todos and unverified claims. On VS Code 1.101 and later it also offers the MCP server to Copilot directly.

JetBrains IDEs: there is no plugin yet. Open the map URL in the IDE's built-in browser (or a window beside the IDE); the UI follows the same New UI look.

4. Deploy plan (free tier)

What runs where

The MCP server must run locally. It reads the project's files as the agent changes them and keeps their history. A hosted MCP server could only do that if every developer uploaded their code to it, which defeats the privacy model and adds latency to every tool call. So there is nothing to host for the MCP server: each user's agent starts mapwright mcp itself.

What you do host: the website (static files: HTML, CSS, JS, the demo data) and the packages.

Website hosting: options compared

The site is about 5 MB of static files (the diagram renderer is about 3.3 MB of that). Any static host works. Free-tier limits change; check the provider's pricing page before you rely on a number below.

Recommendation: Cloudflare Pages for the public site, because static traffic is not metered on the free plan and the demo page is heavy. Use GitHub Pages if you want everything in one place and the repository is public. Firebase Hosting works well too, with the included config, and is the natural pick if the rest of your stack is on Firebase. All three give you HTTPS and a custom domain for free.

Build the site

python scripts/build_site.py

This copies the UI into web/app/ and records a full demo bundle (web/app/demo.json) from the scripted agent session, so the live demo works with no server. The output folder to publish is web/.

Deploy: Cloudflare Pages

Dashboard: Workers & Pages → Create → Pages → Upload assets, drop the web/ folder. Or with the CLI:

npx wrangler pages deploy web --project-name mapwright

To deploy from Git instead: connect the repository, set the build command to python scripts/build_site.py and the output directory to web.

Deploy: GitHub Pages

.github/workflows/pages.yml is included. Push to main, then in the repository Settings → Pages → Source: GitHub Actions. The workflow builds the site and the demo and publishes web/.

Deploy: Firebase Hosting

firebase.json is included (it serves web/, with long cache lifetimes for the renderer and short ones for HTML).

npm install -g firebase-tools
firebase login
cp .firebaserc.example .firebaserc        # put your Firebase project id in it
python scripts/build_site.py && firebase deploy --only hosting

If you later want a shared, hosted map (not built yet)

For teams that want to browse a map without running Mapwright, the path that keeps code private is to publish an export rather than the code: mapwright export -o map/ writes MAP.md (renders on GitHub) plus every diagram and the step history as plain files. Commit that, or upload it to any of the static hosts above. A hosted, read-only MCP server that serves an uploaded export would fit a free serverless tier (Cloudflare Workers, Google Cloud Run or Firebase Functions); it is a possible future addition, not part of this release.

Stop, disconnect, remove

mapwright down                              # stop the daemon
mapwright disconnect claude-code            # remove the MCP entry and hooks (add --scope user if you used it)
pipx uninstall mapwright
rm -rf ~/.mapwright                         # delete all tracked history

Releasing to PyPI

The PyPI name mapwright belongs to an unrelated project, so Mapwright is published as mapwright-agent. The command is still mapwright and the Python package is still mapwright:

pipx install mapwright-agent
mapwright --version

Do not install it into the same environment as the other mapwright package (pipx keeps them apart).

One-time setup (no API token needed: PyPI trusted publishing)

  1. Create accounts at pypi.org (and test.pypi.org to rehearse) and turn on 2FA.
  2. On PyPI go to Your account → Publishing → Add a new pending publisher and enter: project mapwright-agent, owner 1mystic, repository Mapwright, workflow release.yml, environment pypi. (Same on test.pypi.org with environment testpypi.)
  3. On GitHub: Settings → Environments: create pypi (add yourself as required reviewer if you want a manual approval before each release) and testpypi.

Each release

  1. Bump __version__ in src/mapwright/__init__.py (the only place; pyproject.toml reads it), move the CHANGELOG.md "Unreleased" notes under the new version, commit, push.
  2. Rehearse (optional): Actions → release → Run workflow → testpypi, then pipx install --index-url https://test.pypi.org/simple/ mapwright-agent.
  3. Publish: git tag vX.Y.Z && git push origin vX.Y.Z. The workflow checks the tag matches the version, runs the tests, builds, creates a GitHub release with the wheel and sdist attached, and publishes to PyPI once the repository variable PUBLISH_PYPI is true (Settings → Secrets and variables → Actions → Variables; set it after the trusted publisher exists).

Install without PyPI

pipx install git+https://github.com/1mystic/Mapwright.git            # latest main
pipx install git+https://github.com/1mystic/Mapwright.git@v0.2.0     # a release
pipx install https://github.com/1mystic/Mapwright/releases/download/v0.2.0/mapwright_agent-0.2.0-py3-none-any.whl

Actions run only when you start them

tests and website are manual (Actions → workflow → Run workflow); release runs only on a v* tag or by hand. Nothing runs on ordinary pushes, so there are no failure emails.
