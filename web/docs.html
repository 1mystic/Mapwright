Commands

mw is a short alias for mapwright. Every command has --help. Commands that act on a project use the current folder (or --path DIR).

Start and stop

CommandWhat it does
mapwright init [--connect AGENT] [--agents-md [FILE]] [--local | --home DIR] [--apply-ignore]Track this project; the current state becomes step 0. Warns when max_files truncates the scan and suggests ignores for bulky generated/data folders (--apply-ignore saves them)
mapwright init --local / --home DIRKeep this project's history in <project>/.mapwright (or DIR, relative to the project root) instead of ~/.mapwright. Creates it with mode 0700, writes the marker .mapwright/home.json, adds it to .gitignore. With --connect X the MCP entry gets env.MAPWRIGHT_HOME and Claude Code hooks are prefixed with MAPWRIGHT_HOME=…
mapwright open [--print] [--json] [--web [--site URL]]Open the map in the browser (starts the daemon if needed). --web opens the hosted website instead; its page calls your local daemon directly (the token travels in the URL hash, never to the host), and the site is added to web_origins
mapwright up [-d] [--no-watch] · mapwright downStart (foreground or background) or stop the daemon
mapwright watchTrack from the files alone, without the daemon or any agent integration
mapwright forget [--purge] [--yes]Stop tracking this project; --purge also deletes its stored history (only inside the Mapwright home; for a project-local home, that directory and its marker)
mapwright token [--rotate] [--show]Where the local API token lives (never printed unless --show); --rotate writes a new one, then restart the daemon and rerun mapwright open

Stopping Mapwright

I want to…Do this
Stop the map server (daemon)mapwright down (started with up -d or open) · Ctrl-C if mapwright up runs in a terminal
Stop mapwright watchCtrl-C
Stop it if down does not answerpkill -f "mapwright up" (it also frees port 7979)
Stop an agent from recording steps in this projectmapwright disconnect claude-code (also cursor, vscode, …; add --scope user if you connected it for every project). Restart the agent afterwards
Pause automatic steps but keep everything elsemapwright settings auto_step off
Remove all recorded historystop the daemon, then delete the home: ~/.mapwright, or <project>/.mapwright for a project-local home (init --local)
Remove the toolpipx uninstall mapwright-agent (or pip uninstall mapwright-agent)

The daemon only serves the map and watches files; the MCP server and hooks the agent starts are separate and exit with the agent. Stopping the daemon never touches your project files.

Architecture rules

mapwright.toml in the project root (commit it) turns the map into a guardrail. Rules are checked at every step; violations appear in Problems, in the agent's map, in exports, and make mapwright check exit non-zero.

[layers]                       # optional: pin paths to layers when the heuristics guess wrong
"src/app/web/**" = "ui"

[[forbid]]                     # an import that must not exist
from = "ui"                    # a layer name or a path glob
to = ["data"]                  # layers or globs
except = ["src/app/db/types.py"]
reason = "UI goes through services"

[limits]
no_cycles = true               # import cycles between modules
max_complexity = 25            # per function
max_module_lines = 800
# include_tests = true         # tests are skipped unless this is set

Live feedback. When mapwright.toml exists, the Claude Code hook refreshes the project after each edit and compares the rule violations with the state before. If the edit introduced new ones, the agent gets one short line of context (at most 3 items), for example Mapwright: this edit broke a rule: src/ui/v.py [ui] imports src/db/m.py [data]: UI goes through services. Fix it or explain. Each violation is reported once; ones that existed before are never reported; the hook never blocks and stays silent when nothing is new. Turn it off with mapwright settings live_feedback false.

Home resolution: MAPWRIGHT_HOME env, then a project-local home found by walking up from the current directory (or --path, --root, or the hook's cwd) to a .mapwright/home.json marker, then ~/.mapwright. One daemon serves one home, so open/up start it with the project's home and refuse (with a message) if a daemon with a different home holds the port.

Environment: MAPWRIGHT_HOME (default ~/.mapwright), MAPWRIGHT_PORT (default 7979), MAPWRIGHT_ROOT (project for mcp).

Agent protocol

What an agent does with Mapwright, and why each part is shaped the way it is.

The loop

  1. Start of a task: call map. Read structure from it instead of listing directories and opening files.
  2. Plan: todo add for each part.
  3. Before changing a function: symbol NAME to see its callers, callees and tables. Open the file only to edit.
  4. After each meaningful change: step with a short title of what was done.
  5. When a part is finished: todo done ID with the symbol or file you changed as evidence.
  6. When you implement a mechanism (cache, retry, queue, auth …): claim CONCEPT SYMBOL.
  7. Optional: note a module's role; link two symbols the code does not connect directly.

With hooks (Claude Code, opencode), turn ends close a step even if the agent forgets step 4.

Why it is cheap

  • Tool definitions total under 3,000 characters (they are sent with every request).
  • map is capped (default 2,400 characters, about 600 tokens) and shrinks long sections first.
  • No result contains source code. Results point at file:line, so the agent reads only what it needs.
  • The agent sends titles and ids, never diagrams, file lists or summaries. Diagrams, icons, layouts and flowcharts are built from the code by Mapwright.

Why it cannot be gamed

The agent saysMapwright checks
a step titleThe changed files are computed. Titles that mention tests, migrations, routes, tables, docs or infrastructure are checked against what actually changed.
a todo is doneThe evidence must exist and must have changed after the todo was added.
a symbol implements a conceptThe concept's signals must appear in that symbol's code (decorators included). Only a module-level import counts as "weak".
a note or linkThe symbols must exist; when they disappear the note or link is marked stale.

MCP details

  • Transport: stdio, JSON-RPC 2.0, one message per line. Protocol versions 2025-06-18, 2025-03-26, 2024-11-05.
  • Project root: --root, else MAPWRIGHT_ROOT, else the server's working directory (the nearest folder with .git).
  • Errors in a tool are returned as isError: true with a one-line message; the session is never interrupted.
